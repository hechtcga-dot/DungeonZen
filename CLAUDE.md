# Chronosboard

Local-first Windows desktop app for D&D 5e Dungeon Masters. It combines a
detective-board canvas, a multi-storyline temporal engine, a clickable map,
a live-session desk, and AI-assisted creation from raw notes.

## Read these first
- `docs/ARCHITECTURE.md`: stack, process model, temporal engine, AI pipeline
- `docs/DATA_MODEL.md`: tables and rules for stored data
- `docs/FEATURES.md`: feature list, phases, workflows
- `docs/UI_SPEC.md`: screens, wireframes, visual design

## Stack
- Electron (main process: Node) + React + Vite (renderer). No Next.js.
- SQLite via better-sqlite3 + Drizzle ORM. One database per campaign.
- Zustand for UI state. `@xyflow/react` (React Flow) for the board.
- Zod for all validation, including AI structured outputs.
- Open5e API for SRD content; Anthropic or OpenAI SDK for AI features.

Status: Electron, no Next.js, and Drizzle were recommended in planning and
not explicitly confirmed by the owner. React Flow (node graph) is confirmed.
Confirm before scaffolding.

## Non-negotiable rules
1. Local-first. Everything except AI calls and Open5e lookups works offline.
2. Nothing generated by AI or the engine changes campaign data until the DM
   approves it (propose, diff, approve).
3. Nothing is hard-deleted. Changes are superseded; removed items go to
   History and can be revived.
4. Undo works across the whole program. Every write goes through the
   command log.
5. Time is stored as integer minutes from campaign start. Days and hours
   are display only.
6. Enums are stored as strings and validated with Zod (SQLite has no enums).
7. The API key is stored with Electron `safeStorage`, never in the campaign
   folder or the database.
8. Open5e content is copied into the campaign on import, never referenced
   live.
9. Party knowledge is shared across the whole party, tracked per field.
10. AI suggestions must be visibly distinct from DM-authored content.

## Process boundaries
- Main process only: database, file system, AI calls, Open5e calls, key
  storage, exports.
- Renderer: UI only. Talks to main through a typed IPC layer
  (`src/shared/ipc.ts`). No Node APIs in the renderer.

## Suggested layout
```
src/main/        db, engine, ai, importers, exporters, ipc handlers
src/renderer/    screens, components, stores
src/shared/      zod schemas, types, ipc contract
docs/
```

## Build order
Phase 1 Board, Phase 2 Map and Timeline, Phase 3 Live session and review,
Phase 4 Encounter planner and exports, Phase 5 AI ingestion. The temporal
engine (`src/main/engine`) is pure TypeScript with no UI or DB imports and
must have unit tests before any screen depends on it.
